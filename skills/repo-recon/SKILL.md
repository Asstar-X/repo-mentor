# Repo Recon — 项目概览与宏观建模

`repo-recon` 是代码库研读的宏观入口，目标是让开发者在最短时间内建立全局视角、理解系统意图、在本地成功跑通验证，并知道从哪里切入阅读。

---

## 核心准则

1. **默认抓核心**：
   - 自主识别该项目最亮眼、最不可替代的特性去展开（如果是精妙算法就突出算法，如果是架构设计就突出架构，如果是核心规则就突出规则），拒绝千篇一律的套话复述。
2. **以用户为中心**：
   - 用户关注什么、提问偏向什么风格，就顺着用户的视角深入；未指定时以项目的核心价值为主线。
3. **闭环验证（能看也能跑）**：
   - 不只讲抽象概念，必须给出确定性的本地构建与定向单测命令，让用户能立刻在本地验证。
4. **事实第一**：
   - 目录、文件、测试命令与断点建议必须基于仓库真实存在的事实，不脑补不存在的路径。

---

## 四维分析框架

### 1. 项目使命与现实价值
- **现实痛点**：在没有这个项目前，工程师面临什么棘手的问题、性能瓶颈或工程困境？为什么朴素脚本或现成方案无法满足？
- **系统契约**：明确输入什么事件、交付什么产物、在外界留下什么持久化副作用或状态改变。
- **核心逻辑**：直击项目最关键的解法或机制，说明它凭什么解决痛点。

### 2. 开箱验证方案
- **最小构建与运行**：基于检测到的生态，给出最简直接的构建或启动命令。
- **代表性冒烟单测**：挑选 1~2 个覆盖核心路径的单测用例，带上精准过滤参数，让用户在极短时间内得到可信的验证反馈。

### 3. 代码全貌与拓扑组织
- **模块职责映射**：系统核心模块与真实代码目录的对应关系，直接附带物理路径。
- **架构流向图（Mermaid）**：绘制带有清晰数据流动方向、调用链路与组件边界的拓扑图。
- **核心特性深度展开**：针对项目实际突出点（如核心状态流转、并发模型、计算管道等）深入解析。

### 4. 切入路线与演进热点
- **变更热点结合**：结合 `repo-mentor hotspots` 分析出的高频修改文件，指出系统演进最活跃的承重区域。
- **渐进式阅读路线**：规划 3~4 站顺畅的阅读次序（如：入口与上下文装配 -> 核心引擎/调度 -> 热点业务逻辑），明确各站重点看什么。
- **关键断点推荐**：指出 1~2 个最能看清系统运行脉络的代码位置（附带文件与行号锚点）。

## 确定性工具链执行

在执行概览分析时，调用以下确定性 CLI 工具提取客观事实：

```bash
# 1. 扫描生态、技术栈、依赖入口
repo-mentor scan <target_path>

# 2. 提取变更热点文件（定位系统最活跃的演进重心）
repo-mentor hotspots <target_path> --commits 300 --top 10
```
