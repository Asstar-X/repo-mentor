# Repo Recon — 项目概览与快速上手

`repo-recon` 是代码库研读的宏观入口，目标是用大白话帮助开发者在最短时间内建立全局视角、搞懂系统意图、在本地跑通验证，并知道从哪里切入阅读代码。

---

## 核心要求与输出内容

像平时给新入职的同事做项目交底一样，用自然流畅、通俗平实的语言组织：

### 1. 项目是干啥的（日常大白话）
- **解决什么麻烦**：没有这个项目前，大家遇到了什么痛点？为什么普通脚本或常规做法搞不定？
- **输入输出与核心机制**：接收什么输入、输出什么结果、凭什么机制解决了痛点。**严禁使用假大空的套话吹捧**。

### 2. 开箱验证方案（能看也能跑）
- **最小构建或运行命令**：给出最简短、能直接在本地跑起来的命令。
- **代表性冒烟单测**：挑 1~2 个覆盖核心主线的测试命令，让用户能立刻看到测试绿灯反馈。

### 3. 代码全貌与目录职责
- **核心目录与职责映射**：系统最关键的几个目录分别管什么，附带真实物理路径。
- **直观架构拓扑图 (Mermaid)**：绘制清晰简明的数据流动方向图。

### 4. 推荐切入路线
- **结合变更热点**：结合 `repo-mentor hotspots` 分析出的高频修改文件，指出系统演进最活跃的重点代码。
- **3~4 站阅读建议**：按顺畅的次序规划阅读站点（如：入口初始化 -> 核心处理逻辑 -> 业务扩展点），说明每站重点看什么。

---

## ⚠️ 绝对禁令（违者视为严重事故）

1. **严禁戏精加戏**：严禁使用“手术刀”、“两大惨剧”、“惊世骇俗”等浮夸中二比喻。
2. **严禁打公章标签**：严禁在标题或正文中打 `[已验证事实]`、`[工程推导]` 等方括号标签。
3. **严禁原样输出提示词大纲**：严禁输出 `(人话意图与目标契约)` 等提示词原话，按自然段落和小标题表达。
4. **严禁向用户输出验收清单与打勾项**：智能体思考逻辑不得作为 Checklist 打印给用户。
5. **严禁输出伪进度条与说教尾部**：严禁输出“全局研读进度”、“在数学上被严格锁定”等官僚尾巴。
