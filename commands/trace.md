# /trace — 上下文使用场景与调用脉络追踪

> **支撑技能**: [`skills/repo-trace/SKILL.md`](../skills/repo-trace/SKILL.md)

专注于**向外看使用场景**：追踪目标对象在整个系统大图中“用在哪里、在什么实际业务场景下被谁调用、下游交给了谁、数据或流程怎么流经它、遇到异常时如何向外反馈”。

---

## 执行工作流

### 1. 提取目标对象的上下游调用关系
```bash
# 提取目标符号的调用层级
repo-mentor ast <target_path> --symbol <TargetSymbol> --calls
```

### 2. 生成调用脉络报告 (`studies/<repo_name>/traces/<target>_trace.md`)

#### 第一部分：它在什么场景下被使用？(触发环境与业务场景)
> 💡 **认知铁律**：先说清真实场景与触发源头，讲透它在系统大图中的角色。
- **实际使用场景**：在什么具体的实际情况下，系统会需要调用或引用它？
- **最上游的触发源头**：是什么外界事件、用户操作或系统动作最终引发了这一链路？
- **生命周期位置**：在从“事件触发”到“最终结束”的全流程中，它扮演第几棒？由谁唤醒？

#### 第二部分：上下游协同脉络 (关系拓扑与时序)
- **协同脉络图 (Mermaid)**：
  ```mermaid
  flowchart LR
      Trigger["最上游触发源"] --> Upstream["上游 (谁激活/调用它)"]
      Upstream --> Target["[目标对象]"]
      Target --> Downstream["下游 (结果交给了谁)"]
  ```
- **上下游关系拆解**：
  - **上游直接调用方**：是谁在调用、引用或依赖它？位于何处 `[文件路径#L行号]`；
  - **下游承接方**：它处理完毕后，驱动了谁、或把产物传递给了谁去继续消费。

#### 第三部分：具象走读 (拿一个具体实例跑一遍)
选取一个代表性的实例（无论是具体参数值、结构体、配置项还是事件样本），走读流经前后的变化：
- **到达它之前**：输入给它的具体内容长什么样；
- **经过它之后**：经过它的处理，内容发生了什么具体的改变、提炼、更新或包装；
- **最终归宿**：处理后的产物最终被传递到了哪里、对系统产生了什么后续影响。

#### 第四部分：交互方式与失败应对
- **协同交互方式**：上游与它之间是如何协同交互的（直接调用、事件触发、异步队列、规则约束等）；
- **失败与未满足时的反馈**：如果当前对象在执行时发生错误、校验不通过或前置条件不满足，系统会发生什么？错误是如何向上游反馈、捕获或兜底的？

## 3. 自动化质量验证
```bash
repo-mentor verify <target_path> studies/<repo_name>/traces/<target>_trace.md --fix
```
确保触发场景人话清晰，上下游拓扑完整，且引用的文件与行号真实存在。
