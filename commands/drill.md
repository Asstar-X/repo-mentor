# /drill — 硬核问题抽查与答辩复盘

> **支撑技能**: [`skills/repo-drill/SKILL.md`](../skills/repo-drill/SKILL.md)  
> **核心职责**: **Test why it was built and where it breaks, never syntax.** (考底层取舍和崩溃边界，绝不考死记硬背。)

读完代码后检验自己是不是真吃透了。针对目标抛出 2~3 个接地气、直击要害的问题（设计意图、流转形态、极端情况），并对你的回答进行客观专业的复盘交流。

---

## 执行工作流

### 1. 触发抽查
运行 `/drill [目标对象]`（目标可以是整个项目、某个核心模块、关键函数或规则）：
```bash
# 针对目标模块发起抽查
/drill <target>
```

---

### 2. 抛出 2~3 个接地气的硬核考题

不要长篇大论铺垫，直接抛出 2~3 个切中要害的问题：
1. **设计意图题**：作者为什么专门这么写，而不是直接用最普通的方式搞定？避开了什么坑？
2. **实际流转题**：输入一个具体样本流经这里之后，形态发生了什么变化？交给下游的是什么？
3. **极端情况题**：如果把某行核心保护拿掉，或者遇到异常/空输入，系统在什么场景下会出 Bug 或崩掉？

提问后等待用户作答，不提前泄露答案。

---

### 3. 互动答辩与客观复盘

用户作答后，像资深技术搭档一样客观点评复盘：
- **肯定到位的地方**：客观说明哪些部分切中了核心；
- **指出盲区与偏差**：直截了当指出哪里没考虑到或理解有误；
- **给出标准参考**：结合具体物理文件与代码行号，给出清晰权威的标准原理解读。

### ⚠️ 风格红线
- 严禁戏精演戏，严禁以“主考官”、“本座”自居；
- 严禁打公章标签，严禁输出任何打勾清单与伪进度条。
