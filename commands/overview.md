# /overview (别名: /recon) — 项目概览与快速上手

> **支撑技能**: [`skills/repo-recon/SKILL.md`](../skills/repo-recon/SKILL.md)  
> **核心职责**: **Make them get the point and see it run within 30 seconds.** (30 秒内让人搞懂它干啥，并亲手跑通验证。)

像资深同事交底一样，用大白话讲清项目是干啥的、解决什么麻烦、怎么在本地一行命令跑起来、核心目录各管啥、从哪几个文件切入最顺畅。

---

## 执行工作流

### 1. 提取物理事实与演进热点
```bash
# 1. 扫描生态、技术栈、依赖与入口
repo-mentor scan <target_path>

# 2. 提取变更热点文件（定位系统最活跃的演进重心）
repo-mentor hotspots <target_path> --commits 300 --top 10
```

---

### 2. 生成概览说明

按自然段落与日常小标题组织，包含以下要点（**严禁生硬套用格式八股模板**）：

1. **项目是干啥的（日常大白话）**：
   - 痛点与现实需求：没这个项目前大家有什么麻烦，常规方案为啥搞不定；
   - 核心输入输出与机制：凭什么解决了该麻烦，拒绝空洞吹捧。
2. **怎么快速跑起来验证（开箱即验）**：
   - 给出极简的构建或运行命令；
   - 给出 1~2 条定向单测命令，让用户在 10 秒内看到测试绿灯。
3. **代码全貌与目录职责**：
   - 最核心的几个目录分别管什么，附带真实文件路径；
   - 简洁明了的 Mermaid 数据/控制流向图。
4. **推荐切入路线与演进热点**：
   - 结合 Git 变更热点文件，指出系统修改最频繁的承重区；
   - 给出 3~4 站顺畅的阅读次序，以及建议打断点观察的具体代码位置。

### ⚠️ 风格红线
- 严禁戏精演戏，严禁使用中二浮夸修辞；
- 严禁打 `[已验证事实]`、`[工程推导]` 等公章标签；
- 严禁原样输出提示词大纲，严禁在正文中输出任何内部验收打勾清单；
- 严禁在文末拼接“全局研读进度”、“在数学上被严格锁定”等官僚尾巴。
