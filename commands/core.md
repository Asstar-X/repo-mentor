# /core — 核心实现深度剖析

> **支撑技能**: [`skills/repo-core/SKILL.md`](../skills/repo-core/SKILL.md)  
> **核心职责**: **Never show code until the real-world problem is clear.** (现实问题没搞懂之前，绝不提前甩代码。)

专注于**看目标对象自身**：像真人同事聊天一样，用通俗大白话讲透具体对象（函数、类、模块、规则、配置）到底负责什么、内部怎么干的、核心代码怎么写的、边界要注意什么。

---

## 执行工作流

### 1. 定位目标对象
```bash
# 查看目标对象的符号定义与位置
repo-mentor ast <target_path> --symbol <TargetSymbol>
```

### 2. 生成核心剖析（保存至 `studies/<repo_name>/traces/<target>_core.md`）

按自然段落与日常小标题组织，包含以下要点（**严禁生硬套用格式八股模板**）：

1. **它负责什么（日常大白话）**：
   - 用最朴素直白的语言讲清它充当什么角色、解决什么具体麻烦；
   - 严禁堆砌生硬黑话或浮夸比喻；
   - 交代接收什么输入、交付什么产物。
2. **核心工作流程**：
   - 将内部主线梳理为 3~4 个直观步骤，说清内部是怎么跑通的。
3. **关键代码与实现点**：
   - 截取 5~15 行最核心真实代码，附带可点击链接：`[文件路径#L起始行-L结束行]`；
   - 提炼背后的设计意图，解释为什么这么写，**严禁机械逐行英译中**。
4. **边界考量与踩坑点**：
   - 面对非法输入、空值或特殊边界时如何防御容错，作者规避了什么隐患。

### 输出规范
- 保持客观平实的同行技术交流风格，杜绝夸张比喻与空洞套话；
- 自然引用源码行号链接，不输出提示词引导句、置信度标签、内部打勾清单或进度条尾巴。

---

## 3. 自动化质量验证
```bash
repo-mentor verify <target_path> studies/<repo_name>/traces/<target>_core.md --fix
```
确保行文是大白话，引用的文件与行号真实存在。
