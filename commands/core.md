> **支撑技能**: [`skills/repo-core/SKILL.md`](../skills/repo-core/SKILL.md)

专注于**向内看自身实现**：剖析任意具体目标对象（函数、类、模块、Skill 规则、配置工作流）“自身是干什么的、内部如何分步运作、核心内容怎么实现的、在边界情况下如何防御”。

## 执行工作流

### 1. 定位目标对象
```bash
# 查看目标对象的符号定义与位置
repo-mentor ast <target_path> --symbol <TargetSymbol>
```

### 2. 生成核心剖析报告 (`studies/<repo_name>/traces/<target>_core.md`)

#### 第一部分：它是干什么的？(人话意图与目标契约)
> 💡 **认知铁律**：先用毫无门槛的大白话讲清现实意义，严禁一上来堆砌实现细节或代码行号。
- **核心职责**：用通俗人话讲清楚，这个对象到底负责什么事情。
- **存在意义**：为什么需要专门由它来处理这件事情？没有它会缺少什么？
- **基本契约**：
  - **输入 / 前提**：它基于什么数据、参数或触发条件开展工作；
  - **产出 / 效果**：它执行完后，产出了什么结果、做出了什么改变或确立了什么规范；
  - **状态影响**：是否修改了外部传入的对象、更新了系统环境或产生外部变更（纯函数或无状态规则标明无副作用）。

#### 第二部分：它是怎么展开工作的？(内部处理脉络)
> 💡 概括该对象内部把任务分成了哪几个先后步骤来完成（自适应提炼 3~4 步）：
- **步骤 1: [前期准备 / 输入处理]** — 做了什么前置检查、格式规整或环境初始化；
- **步骤 2: [核心逻辑 / 主体处理]** — 最核心的主体工作内容与转换规则；
- **步骤 3: [收尾输出 / 结果交付]** — 如何完成并输出最终交付产物。

#### 第三部分：核心内容与实现事实 (关键引用)
- **源码位置**：`[文件路径#L起始行-L结束行]`
- **关键切片 (5~15 行)**：截取其最承重、最关键的核心切片（无论是代码、规则还是配置）。
- **实现原理剖析**：
  - 这几行核心内容的设计意图是什么？
  - 它为什么能达成上述目标？关键逻辑是如何推进的？

#### 第四部分：边界处理与特殊情况
- **异常 / 边界考量**：遇到极限情况、非法输入或特殊冲突时，它是如何做防御性兜底或容错处理的？
- **设计权衡**：为什么作者采用目前的实现或表述方式？规避了什么潜在问题？
